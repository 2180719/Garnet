A personal agent you can actually read.

Ruby runs on your own server or laptop and answers you on Telegram, Signal or Discord. Its memory is two Markdown files with a hard size limit, and it asks before it writes a file.

The whole thing is about 9,400 lines of TypeScript with two runtime dependencies. You can read all of it, and so can your coding agent. It hasn't reached 1.0 yet; Status says what that means in practice.

What it does

One process holds everything: the chat channels, a durable inbox and outbox in SQLite, the agent loop, the scheduler and an optional HTTP API. A message is stored before Ruby acts on it, so a restart picks up where it left off and a duplicate delivery doesn't run twice.

Channels
Telegram through the bot API, Signal through a local signal-cli daemon, and Discord direct messages. Someone Ruby doesn't know gets a six-character pairing code and nothing else until you run ruby pair approve on the host.
Approvals

Every tool capability is set to allow, ask or deny. Out of the box, reading files is allowed, writing asks, and running commands is off. An approval covers one operation and expires after a day. In chat it looks like this:

Memory
MEMORY.md holds Ruby's own notes, capped at 2,200 characters. USER.md holds what it knows about you, capped at 1,400. When a file is full, Ruby has to consolidate instead of appending forever. Every change is versioned, so ruby memory rollback undoes a bad edit.
Skills
Folders with a SKILL.md, in the agentskills.io format. Only each skill's name and a one-line summary go into the prompt. If you edit a skill by hand it becomes locked, and Ruby can only propose a diff for you to accept. It never downloads skills from anywhere.
Schedules
Cron jobs and heartbeats, each with its own token budget and timeout. A heartbeat can watch a file or a URL and only wake the model when it changes, so an hour in which nothing happened costs no tokens.
Long chats
When a conversation gets large, older turns are summarized and the last two are kept word for word. The system prompt stays fixed for the session so the provider's prompt cache keeps working.
Commands
run_command runs each command in a fresh Docker container: debian:stable-slim, no network, 512 MB of memory. There is also a local backend, and the config says plainly that it is not a security boundary.
API
Off until you run ruby api enable. Then it serves an OpenAI-compatible /v1/chat/completions on 127.0.0.1:7311, so existing chat apps can connect with a scoped key. Keys are stored hashed and every request is rate-limited.
Models
Anthropic, or anything that speaks the OpenAI API: OpenRouter, Ollama, llama.cpp, vLLM, LM Studio.
Housekeeping
ruby service install writes a systemd unit or a launchd plist. ruby backup copies the database, config, memory, skills and workspace. ruby import openclaw (or hermes) brings over memory, persona and skills, as a dry run unless you add --apply. It never copies secrets.

Defaults

Ruby exists partly because of what went wrong elsewhere: agent gateways left open on the internet, heartbeats that paid a large model to report that nothing had changed, skills from public registries that turned out to be malware. So the defaults are conservative, and loosening them is a config edit you make on purpose.

A few things aren't settings at all. Ruby refuses to listen on a public address until at least one API key exists. Tools can only touch one workspace directory, ~/.ruby/workspace unless you point it elsewhere. API keys and bot tokens are referenced by the name of an environment variable, never stored in the config, and are redacted from logs. If you ask for the Docker sandbox and Docker isn't there, you get an error rather than a quiet fallback to running on the host. ruby config explain prints every setting with its default.

The code

Node 22.18 runs the TypeScript directly, so there is no build step. Storage is SQLite through the built-in node:sqlite. The only runtime dependencies are zod and the Anthropic SDK, and the lint script fails if someone adds a third without a reason.

Modules talk to each other only through their index.ts, and each folder has an AGENTS.md saying what it owns and what it must not do. Despite the name, those files are written for people as much as for agents. They also let a coding agent asked to change Ruby find the right file without reading everything first. npm run check runs lint, the type checker and the tests, offline, in one go.

Status

Pre-release, version 0.1.0. Everything described above is in the repository, with tests. The tests run offline against a fake model and fake channels; Ruby has not yet been run against live Telegram, Signal or Discord servers or real provider APIs as part of testing. Expect rough edges the first time it meets a real bot.

The dashboard's API is done and its interface is being built. Still to come before a 1.0: an encrypted secret store (today secrets live in an env file with mode 600), failure-injection tests, a docs site, and the live tests above. The plan tracks each phase.

Install

You need Node.js 22.18 or newer, and an Anthropic key or an OpenAI-compatible endpoint once you're past the fake model.

For Telegram, create a bot with @BotFather, put TELEGRAM_BOT_TOKEN in ~/.ruby/env, set channels.telegram.enabled to true, and run ruby start. The README covers the rest, including the API and keeping it running as a service.

Talk to it

This box talks to a Ruby instance running a small model with no tools and no memory, on a daily budget. Whatever you type is sent to that server, so leave out anything private.
