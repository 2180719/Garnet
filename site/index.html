A personal agent you can actually read.

Ruby is an open-source, self-hosted AI agent you reach through Telegram, Signal, Discord, a dashboard or an API. It is designed to be small enough to audit, secure by default, and frugal with tokens.

Why Ruby

Agents shouldn't be a black box you hand the keys to.

Many agent harnesses grow into sprawling codebases with exposed defaults and surprise bills. Ruby is being built as the opposite.

Small and auditable

One job per module, a predictable layout, and a fast offline test suite. The goal is a codebase a person, or their own agent, can read end to end.

Secure by default

Designed to bind to loopback, refuse public exposure without auth, and ask before consequential actions. Safe settings first, opt-in for the rest.

Token-efficient

A stable prompt prefix, bounded memory, tools loaded on demand and cheap checks before any model call, so idle time costs close to nothing.

Yours

Runs on your VPS or computer. Memory, persona and skills are plain files you can open, edit and version. No telemetry.

Features

Designed around how you actually use an agent.

Everything below is the design target from the project plan. Ruby is pre-release, and none of it should be assumed to be shipped yet.

Multi-channel gateway

One gateway for Telegram, Signal, Discord, the dashboard and the API. Durable inbox and outbox, deduplication, one active run per session, and pairing codes for unknown senders.

Roadmap: Telegram first

Opt-in, key-gated API

Off by default. When enabled: scoped, revocable, hashed keys, rate limits, an audit log and an OpenAI-compatible /v1/chat/completions endpoint, so existing chat frontends can connect.

Designed

Bounded memory and skills

Hard-capped MEMORY.md and USER.md, versioned and rollback-able. Skills are plain SKILL.md files. Your edits are locked, and the agent can only propose a patch.

Designed

Heartbeats that don't burn tokens

Scheduled checks run cheap, deterministic pre-checks first (file changed, URL hash changed, exit code) and wake the model only when something does.

Designed

Sandboxed tools and approvals

Permission profiles set each capability to allow, ask or deny. Approvals are bound to one operation and expire. Sandbox backends: local, Docker, then SSH.

Designed

Opt-in dashboard with achievements

A light dashboard for sessions, approvals, memory, schedules and usage, plus achievements unlocked by real milestones. Stored locally, and never phoning home.

How it works

One gateway, one source of truth.

Channels stay thin. The gateway owns delivery and routing, and the runtime owns the agent loop. Tools and memory sit behind a policy layer.

  1. Message arrives. The sender is verified, the message is deduplicated and persisted, then queued on that session's lane.
  2. Context is built. A stable prefix, a frozen memory snapshot and recent turns keep prompt caching effective.
  3. Tools are gated. Each call is validated and checked against policy, and anything risky waits for your approval.
  4. Reply is honest. Completion reports say what was done, what was verified and what remains.

Security posture

Designed to be safe before it is convenient.

These are design commitments from the plan. They are targets for the implementation, not audited claims.

  • Loopback by default. A non-loopback bind is refused unless an API key exists.
  • Hashed, scoped API keys. Salted scrypt hashes, expiry, revocation, rate limits and an audit log.
  • Pairing for unknown senders. One-time codes approved by the owner. Display names are never identity.
  • Approvals that mean something. Persisted, tied to a single operation, from an authorized identity, and expiring.
  • Real isolation or an error. An isolated profile never silently falls back to an unsandboxed backend.
  • Secrets stay out of prompts. An encrypted store, credentials injected by name and redacted from logs.
  • No automatic third-party skills. Only local or reviewed skills, and no third-party code run in-process.
  • No tracking. No telemetry in the agent, and none on this website.

FAQ

Straight answers.

Can I use Ruby today?

Not yet. Ruby is pre-release and in active development. The plan is public, and the code and docs will land in the repository as the build phases progress.

Where does it run?

On your own VPS or computer, as one service managed by systemd or launchd. A Docker image is optional.

Which models will it support?

The plan starts with the Anthropic Messages API, then an OpenAI-compatible adapter for providers such as OpenRouter and local models.

Is there a skill marketplace?

No. A public marketplace is a non-goal for v1. Ruby is designed to install only local or reviewed skills, in the plain SKILL.md format.

Does this website track me?

No. There are no analytics, cookies, third-party requests or web fonts. The only thing stored in your browser is your light or dark theme choice, if you make one.

How can I help?

Read the plan and open an issue or discussion on GitHub. Small, well-tested modules are easy to contribute to by design.
