# models

Provider adapters implementing `ModelAdapter` from contracts.

- `FakeModel`: scripted and offline, for tests and `--fake`. Records every request. `onboardingScript(mode)` (`fake-onboarding.ts`) is the scripted wake-up conversation: one question per owner reply, then real `set_profile` and `memory` calls, then a report read from the tool results. Modes `broken-tools` (every save has invalid input) and `no-tools` (never calls a tool) exercise the fallback. `garnet chat --onboard --fake` plays the `ok` script.
- `AnthropicModel`: official SDK, streaming, with a cache breakpoint on the system prompt plus automatic conversation caching, `eager_input_streaming` tools, server-side refusal fallback (`fallbacks: "default"`) and configurable effort. SDK retries are off; the runtime retries. Mid-stream `error` events have no HTTP status and are classified by error type (`overloaded_error`, `api_error`, `rate_limit_error`, `timeout_error` are transient). Empty text blocks and other providers' blocks are never sent (the API rejects empty text).
- Adapter rules: end every stream with exactly one `done` or `error` event; never throw for provider failures; map errors to `provider_transient`/`provider_fatal`/`cancelled`; keep unknown blocks as `provider` blocks in their original position so history replays byte-for-byte.
- Tests use recorded SSE through an injected `fetch`; never call the network in `npm test`.
- `OpenAICompatibleModel`: OpenAI Chat Completions over global `fetch` (OpenRouter, Ollama, llama.cpp, vLLM, LM Studio). Streams SSE with `stream_options.include_usage`; sends the output cap as `max_completion_tokens` for `api.openai.com` and `*.openai.azure.com` (OpenAI's reasoning models reject `max_tokens`) and as `max_tokens` elsewhere (OpenRouter and local servers document only that), overridable with `tokenParam`; the cap is clamped so a generous prompt estimate (3 chars per token) plus the output fits `contextWindow` (never below 1024 unless less was asked), because vLLM and llama.cpp reject prompt + max_tokens over the model length; `Authorization` only when an API key is set, `X-Title: Garnet` only for openrouter.ai. Tool results become `role: tool` messages emitted before the turn's user text; foreign provider blocks are dropped; its only own blocks are the tool-call extras below. Cached prompt tokens (and OpenRouter's `cache_write_tokens`) are subtracted from `inputTokens` and reported as `cacheReadTokens`/`cacheWriteTokens`; missing usage stays `null`. A tool call without an id gets a fresh unique one. A stream that stops early (mid-stream error, consumer stopped) cancels the response body so the connection is released. Unparseable tool arguments are passed through as the raw string for the executor's repair step. A tool call's vendor `extra_content` (Gemini's `google.thought_signature`, without which Gemini 3 rejects the next request with HTTP 400) is stored as an unbound `provider` block (`{ callId, extra }`) after the calls and echoed back on that call when history replays. Mid-stream `data: {"error":...}` lines map to `provider_fatal` (or transient when they say overloaded/rate limit).
- `GeminiModel` (`gemini.ts`): Gemini through its OpenAI-compatible endpoint (`https://generativelanguage.googleapis.com/v1beta/openai/`), as a subclass of `OpenAICompatibleModel` rather than a native adapter, because tools, SSE streaming with usage in the last chunk and `image_url`/`file` parts all work there. The preset sets the base URL, `Authorization: Bearer` (secret name `GEMINI_API_KEY`), `max_tokens` for the output cap, id `gemini:<model>`, media on (override with `vision`/`pdf`) and a 1M context window unless the caller passes one (`createModel` passes the catalog's, see `src/catalog`). There is no model table to keep current: ids and prices come from the model catalog and the provider's own `/models` list. Not exercised against the live API by the tests (recorded SSE only).
- `SwitchableModel` (`switchable.ts`): wraps the model so `/provider` can swap the adapter between calls. `id` and `capabilities` follow the current adapter; a call in flight is never affected. History replay across providers is safe because every adapter drops provider blocks it did not create (so Claude's signed thinking is not sent to Gemini and is replayed again if the chat swaps back).
- Attachments: an `attachment` block with `data` becomes a native block (Anthropic: `image` with a base64 source for JPEG/PNG/GIF/WebP, `document` with a base64 PDF source and the file name as `title`; OpenAI-compatible: `image_url` with a data URL, `file` with `file_data` as a data URL). Without `data` it is sent as `attachmentText`. OpenAI-compatible user turns stay plain strings unless they carry media (text-only local servers reject part arrays). `capabilities.media`: Anthropic images and PDFs on unless `vision`/`pdf` are false (images up to 3.75 MB raw, since the API caps base64 images at 5 MB); OpenAI-compatible off unless configured. `FakeModel` takes `{ media }` (default: both on).
