# models

Provider adapters implementing `ModelAdapter` from contracts.

- `FakeModel`: scripted and offline, for tests and `--fake`. Records every request.
- `AnthropicModel`: official SDK, streaming, with a cache breakpoint on the system prompt plus automatic conversation caching, `eager_input_streaming` tools, server-side refusal fallback (`fallbacks: "default"`) and configurable effort. SDK retries are off; the runtime retries. Mid-stream `error` events have no HTTP status and are classified by error type (`overloaded_error`, `api_error`, `rate_limit_error`, `timeout_error` are transient). Empty text blocks and other providers' blocks are never sent (the API rejects empty text).
- Adapter rules: end every stream with exactly one `done` or `error` event; never throw for provider failures; map errors to `provider_transient`/`provider_fatal`/`cancelled`; keep unknown blocks as `provider` blocks in their original position so history replays byte-for-byte.
- Tests use recorded SSE through an injected `fetch`; never call the network in `npm test`.
- `OpenAICompatibleModel`: OpenAI Chat Completions over global `fetch` (OpenRouter, Ollama, llama.cpp, vLLM, LM Studio). Streams SSE with `stream_options.include_usage`; sends the output cap as `max_completion_tokens` for `api.openai.com` and `*.openai.azure.com` (OpenAI's reasoning models reject `max_tokens`) and as `max_tokens` elsewhere (OpenRouter and local servers document only that), overridable with `tokenParam`; the cap is clamped so a generous prompt estimate (3 chars per token) plus the output fits `contextWindow` (never below 1024 unless less was asked), because vLLM and llama.cpp reject prompt + max_tokens over the model length; `Authorization` only when an API key is set, `X-Title: Ruby` only for openrouter.ai. Tool results become `role: tool` messages emitted before the turn's user text; foreign provider blocks are dropped and it creates none. Cached prompt tokens (and OpenRouter's `cache_write_tokens`) are subtracted from `inputTokens` and reported as `cacheReadTokens`/`cacheWriteTokens`; missing usage stays `null`. A tool call without an id gets a fresh unique one. A stream that stops early (mid-stream error, consumer stopped) cancels the response body so the connection is released. Unparseable tool arguments are passed through as the raw string for the executor's repair step. Mid-stream `data: {"error":...}` lines map to `provider_fatal` (or transient when they say overloaded/rate limit).
- Attachments: an `attachment` block with `data` becomes a native block (Anthropic: `image` with a base64 source for JPEG/PNG/GIF/WebP, `document` with a base64 PDF source and the file name as `title`; OpenAI-compatible: `image_url` with a data URL, `file` with `file_data` as a data URL). Without `data` it is sent as `attachmentText`. OpenAI-compatible user turns stay plain strings unless they carry media (text-only local servers reject part arrays). `capabilities.media`: Anthropic images and PDFs on unless `vision`/`pdf` are false (images up to 3.75 MB raw, since the API caps base64 images at 5 MB); OpenAI-compatible off unless configured. `FakeModel` takes `{ media }` (default: both on).
