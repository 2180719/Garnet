# config

Loads `<GARNET_HOME>/config.json`, validates it with zod, migrates old versions (keeping a `.bak-vN` backup), and redacts secrets for display.

- Public API: `loadConfig`, `writeConfig`, `parseConfig`, `defaultConfig`, `configSchema`, `redact`, `garnetHome`, `pathsFor`, `loadEnvFile`, `parseEnv`, `removeFromEnvFile`, `setInEnvFile`, `secretNames`, `envVar`, `unknownGarnetEnv`, and the editing helpers in `edit.ts` (`changeConfig`, `getConfigValue`, `parseConfigValue`, `showConfigValue`) behind `garnet config get|set|unset`.
- Every field needs `.describe()`; `garnet config explain` and the dashboard render them.
- `persona.ts` owns the `<!-- garnet setup -->` block in `config.persona`: `readPersona`, `writePersona`, `validBasic` (single line, no comment markers), `DEFAULT_NAME`, `PERSONA_MAX`. `garnet setup`, the onboarding fallback form and the `set_profile` tool all go through it.
- `timezone` (optional, IANA) is the owner's zone for schedules and reminders; unset means the host's. `jobSchema` is exported for jobs stored outside config (the scheduler's `JobBook`).
- Defaults must be safe: external access off, loopback only, `exec` denied.
- Named providers (config version 3): `model` is the provider named `default`; `providers` is a map of more (names are lowercase slugs, `default` reserved, validated by `PROVIDER_NAME_RE`); `activeProvider` names the one in use and must exist. Use the helpers in `providers.ts` (`listProviders`, `activeProvider`, `keyEnvOf`, `withActiveProvider`, `withProvider`, `withoutProvider`, `providerNameProblem`), never `config.model` directly, for "the model in use". `apiKeyEnv` has no schema default: `keyEnvOf` gives `ANTHROPIC_API_KEY` for anthropic and `GEMINI_API_KEY` for gemini. `secretNames` lists every provider's key name. A new named custom provider (setup, `garnet providers add`) gets its own key name from `providerKeyEnv(config, name)` (`my-laptop` -> `MY_LAPTOP_API_KEY`; prefixed `GARNET_` when that would start with a digit or equal a well-known or already-used key name); configs already on a shared name keep it, so no stored key is lost. `providers.*.provider`, `providers.*.baseUrl` and `activeProvider` are protected (with `*Env`): they choose where prompts and keys go.
- Schema change checklist: bump `CONFIG_VERSION`, add a migration in `migrations.ts`, add a test in `config.test.ts`.
- Must not: read secrets. Config names environment variables or stored secrets (`apiKeyEnv`, `tokenEnv`; `secretNames` lists them); `main.ts` resolves them through `src/secrets`. The env-file helpers (`env.ts`) are the one exception: they parse and rewrite `<home>/env` for the CLI.
- `sandbox.*` (backend and every `sandbox.ssh.*` option) is protected. `sandbox.ssh` is a strict object (a typo or a literal `passphrase` is an error) and the ssh backend requires `host`, `user`, `workdir` and `identityFile` or `agent`. The key passphrase is `sandbox.ssh.passphraseEnv`, a secret NAME; `secretNames` lists it only when the backend is ssh. `hostKeyChecking` defaults to `strict`.
- `skills` and `connectors` (version 2): optional built-ins, all off by default. Each has `enabled` (global) and `channels` (overrides keyed by scope, `SCOPE_RE`: a channel or surface, `<channel>:<chatId>`, `api:<keyId>`, `job:<id>`, `route:<name>`) with `enable`/`disable` lists. `extensions.ts` holds the names (`BUILTIN_SKILLS`, `CONNECTORS`), `resolveToggles` (global, then each scope broadest first; the narrowest wins), `resolveScopes`/`activeNames` (the one resolver for a conversation: a chain like `resolveToggles`, or for a shared conversation with `feeds` a disable in any feeding scope or the route wins, then the route's enable, then every feeding chain must be on) and `setToggle` (the CLI's edit). Connector settings name secrets (`connectors.github.tokenEnv`, `connectors.calendar.urlEnv`); `secretNames` includes them when the connector is on anywhere. `connectors.github.apiUrl`, `repos` and `write` are protected (where the token goes and what it may do); `apiUrl` must be https (plain http only for localhost, 127.0.0.1 or [::1]).
- `media.transcription.*` and `media.pdfText.*` are protected (`protected.ts`): they choose a host command or where voice notes and a key are sent. `secretNames` includes `media.transcription.apiKeyEnv` when that backend is used. `model.vision`/`model.pdf` are optional; unset means the provider default.
- Settings never come from the environment: only secrets, `GARNET_HOME` and the bootstrap variables in `docs/CONFIGURATION.md` are read. A new `GARNET_*` variable must be added to `KNOWN_GARNET_ENV` (`env.ts`) and to that table, or doctor flags it as unread (doctor passes `secretNames(config)` to `unknownGarnetEnv`, so a secret name the config points at is never flagged; a `GARNET_*` default secret name such as `GARNET_CALENDAR_URL` goes in `KNOWN_GARNET_ENV`). `changeConfig` refuses credential-shaped values and non-name values in `*Env` fields; keep that in step with `redact.ts`.
- Every schema field needs `.describe()`; `edit.test.ts` fails otherwise.
