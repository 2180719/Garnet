# connectors

Built-in, optional integrations with outside services. Each connector is one tool (`calendar`, `github`, `weather`) built on the SSRF-guarded `WebFetcher` from `src/tools`. Everything here is off until config turns it on (`connectors.enabled`, `connectors.channels`); see `docs/CONNECTORS.md` for the owner's view and why this first set.

- Public API: `CONNECTOR_INFO` (per connector: tool name, summary, capabilities, hosts and secret names, for the CLI and doctor without building anything), `connectorTools(names, settings, deps)` (builds the tools), the tools themselves (`githubTool`, `calendarTool`, `weatherTool`), and the ICS reader (`parseIcs`, `occurrences`, `parseWhen`, `parseDuration`, `parseDurationParts`, `toInstant`).
- `ConnectorDeps`: `fetcher` (the only HTTP client), `secret` (resolves a secret *name*: environment, then the encrypted store), `timeZone` (the owner's), `now` (tests). Credentials are resolved at call time, never stored in the tool, never put in output, errors, approval summaries or targets.
- Policy: every call needs `net.fetch`, checked with `targets` = the exact request URLs (so `web.allowHosts` host scopes apply, and untrusted-content containment escalates it like any fetch; connector endpoints are *not* trusted endpoints, because the model composes the query). A call that publishes text (GitHub `comment`) also needs `message.send` through `capabilitiesFor`; the strictest verdict wins and `summarize` shows the full text.
- Untrusted output: every connector sets `untrustedOutput` and returns `ToolOutput.untrusted` with a short source (`github issue owner/repo#3`, `calendar feed at host`) and the links it found. Outside strings go through `clean` (control and bidi characters removed) and are clipped.
- Registration and scope live in `src/main.ts`: a connector's tool is registered when the connector is on somewhere, or an existing session froze it into its extras (`SessionStore.frozenConnectors()`, so that session keeps it through a restart and compaction after config turned it off), and only while `net.fetch` is not `deny`; the runtime freezes it into a session only when the connector is on for that session's scope (`Agent.connectorOfTool`, `selectExtras`). The executor refuses tools outside the session's frozen set.
- GitHub: REST v3 with `Accept: application/vnd.github+json` and a bearer token from `connectors.github.tokenEnv` (optional for public repositories). `repos` limits which repositories it reads or comments on (`owner/name`, `owner/*`; search results and notifications from others are hidden). `owner/name` is validated so a path segment can never be `.` or `..`. `comment` exists only with `write: true`. A non-default `apiUrl` (GitHub Enterprise Server) is the fetcher's `trustedOrigin`, so it may be on a private network; the token is only ever sent to `apiUrl` (the fetcher drops headers on a cross-origin redirect).
- Calendar: read-only. The feed address is a secret (`urlEnv`): private ICS addresses embed a password. Only its origin is used as the policy target and in messages, and a fetch error is rethrown with its category but a fixed host-only message (the fetcher's own messages can quote a redirect target or the address); `user:password@` in the address becomes a Basic auth header. The owner chose the address, so its origin is a `trustedOrigin`. `ics.ts` reads VEVENTs (folded lines, TZID, all-day dates, DURATION, EXDATE, RECURRENCE-ID overrides, CANCELLED) and expands RRULE FREQ DAILY/WEEKLY/MONTHLY/YEARLY with INTERVAL, COUNT, UNTIL, BYDAY (with ordinals in a month), BYMONTHDAY, BYMONTH, WKST, in the event's own zone so wall-clock times survive DST. Days are nominal (RFC 5545 3.3.6): an all-day event without an end lasts until the next local midnight, a date DTEND counts whole days, and a DURATION keeps its days apart from its exact hours/minutes/seconds (`parseDurationParts`) and adds them on the calendar in the event's zone per occurrence; a date-time DTEND is an exact length. Anything else (BYSETPOS, hourly rules, Windows zone names) is shown with a note, never guessed.
- Weather: Open-Meteo geocoding and forecast, keyless; metric or imperial from config.
- Must not: read config files or the secret store directly, log, or call anything but `WebFetcher`. No new runtime dependencies (zod only, like other tool modules).
- Adding a connector: add its name to `CONNECTORS` and its settings to `connectors` in `src/config` (bump the config version), a `<name>.ts` with one tool following the rules above, an entry in `CONNECTOR_INFO` and `connectorTools`, offline tests with an injected resolver and a local server, doctor checks, and a section in `docs/CONNECTORS.md`.
- Tests are offline: `connectors.test.ts` drives the tools with a recording stub in place of `WebFetcher` (request planning, headers, errors, formatting, the executor's policy checks), plus one test through a real `WebFetcher` and a local HTTP server (a resolver points hosts at it) to check that an owner-configured host may be private and Open-Meteo may not.
