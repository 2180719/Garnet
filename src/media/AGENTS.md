# media

Files in and out: photos, documents and voice notes from chats, the HTTP API and `/attach` in the terminal; `send_file` to chats.

- Public API: `MediaStore` (content-addressed files under `<home>/media`), `MediaIngest` (store, sniff, transcribe, extract; `unreadableReply`), `OpenAITranscriber`/`CommandTranscriber`, `runOnFile`, `detectMime`/`sniffMime`/`kindOf`, `sendFileTool`.
- Storage: `med_<first 32 hex of sha256>.bin`, mode 0600, outside the workspace (tools cannot read or change it), written once. The event log keeps only `AttachmentRef`s (`contracts/messages.ts`) plus derived text; bytes are never inlined into events. The runtime loads bytes per request (`AgentDeps.loadAttachment`) and `context/attachments.ts` decides what the model gets.
- Types: a recognized signature always wins over the claimed type or name, so a file claiming to be an image or PDF without the signature is not treated as one. Text types must decode as UTF-8 without binary control bytes. Unknown is `application/octet-stream`.
- Limits: `media.maxBytes` per file (checked against the platform's declared size before downloading, and again while reading the body); long derived text is cut at `media.maxTextChars` with the full text saved as an artifact (`read_artifact`).
- Derived text at ingest (recorded in the user turn, so the log shows exactly what the model saw): audio → transcript (`media.transcription`); PDFs → nothing when the model reads PDFs natively, else `media.pdfText.command` output if configured; text, markdown, CSV, JSON, YAML, XML → the decoded text; video and other binaries → a note. Failures become a `note`, never an exception.
- Honest replies: `unreadableReply` returns a direct answer when a message has no text and nothing in it is readable (voice note with no transcription, image for a text-only model, a file that failed to download). The gateway sends it instead of running the model.
- Commands (`runOnFile`): no shell, argv with `{input}` (appended if absent), a private temp dir with an extension matching the type, a minimal environment (PATH, HOME, LANG, LC_ALL, TMPDIR; no keys or tokens), timeout and output cap, temp dir always removed. These run on the host and parse untrusted files, so they are opt-in and protected from the admin API (`config/protected.ts`).
- Transcription over HTTP: multipart `file` (named `audio.<ext>` matching the sniffed type, since providers pick the decoder by extension), `model`, `response_format=json`, optional `language`; reads `{ text }`. The key is a bearer token and is redacted from errors. Works with OpenAI, Groq (`https://api.groq.com/openai/v1`, `whisper-large-v3-turbo`), speaches/faster-whisper-server, and whisper.cpp's server (`--inference-path /v1/audio/transcriptions --convert`, or set `path: "/inference"`).
- `send_file`: capability `message.send` (ask by default), workspace paths only (containment re-checked on the real path at run time), copied into the media store first so a delayed or retried delivery does not depend on the workspace file. Target: a job session's `notify` chat, else the chat the session last heard from (`GatewayStore.lastChatForSession`); terminal/API/dashboard sessions get a clear error. Size is checked against `UPLOAD_LIMITS` from channels and `media.maxBytes`. Delivery goes through the durable outbox like any reply. Like every `message.send` tool it goes through containment: when the session has read untrusted content, an `allow` becomes `ask` and the approval says why.
- Taint: images, PDFs and other files the owner passes on taint the session (`file "name" sent in chat`, recorded by the runtime), because they are usually written by someone else; voice notes (the owner's own words) do not.
- Retention: `MediaStore.prune(before, inUse)` deletes files older than the cutoff that are not in `inUse` (ids referenced by events or pending messages); `put` refreshes the mtime of an existing file so a re-sent file is not pruned under a new reference.
- Must not: call models, import the gateway, or put bytes or keys in logs, events or tool output.
