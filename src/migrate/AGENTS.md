# migrate

Imports an OpenClaw or Hermes Agent install into Garnet: `garnet import <openclaw|hermes> [--from <dir>] [--apply] [--raise-caps] [--pairings] [--persona keep|merge|replace] [--no-jobs]`.

- Public API: `planImport(source, fromDir, opts)` (pure read), `applyImport(plan, deps, opts)`, `formatPlan`, `formatResult`, `runImport(args, io, deps)` (the CLI body, async; the caller injects stores so this module never imports `main.ts` — `src/cli/import.ts` builds the deps), `importedArchiveSection(workspace)` (the system prompt section pointing at `imported/`), `personaHasOwnText`/`splitPersona`.
- Default is a dry run. `--apply` is the only thing that writes. Pairings need `--pairings` (or a yes in the setup wizard) on top: each paired sender is an owner. Memory caps are raised only with `--raise-caps` (or a yes). In the wizard `deps.ask` asks; scripted runs get the safe answer (off / keep).
- Source layouts: OpenClaw = `<home>/workspace/{SOUL,IDENTITY,AGENTS,USER,MEMORY,HEARTBEAT,TOOLS}.md`, `memory/YYYY-MM-DD.md`, `skills/<name>/SKILL.md`, `openclaw.json` (JSON5, read with `json5.ts`), `state/openclaw.sqlite` (2026.9.x: automations, heartbeat scratch, approved senders), `.env`. The workspace is `OPENCLAW_WORKSPACE_DIR`, else `agents.defaults.workspace`, else `<home>/workspace`, else `--from` itself; a workspace outside the home gets its own scanner and its files are archived under `imported/openclaw/workspace/`. Default home honors `OPENCLAW_STATE_DIR`/`OPENCLAW_PROFILE`; environment hints are ignored when `--from` is given. Hermes = `<home>/memories/{MEMORY,USER}.md` (`§`-separated), `SOUL.md`, `skills/[category/]<name>/SKILL.md`, `skills/.bundled_manifest` (`name:md5`), `cron/jobs.json`, `platforms/pairing/<platform>-approved.json` (or legacy `pairing/`), `config.yaml`, `.env`; default home honors `HERMES_HOME`; `profiles/<name>` are warned about with the `--from` to use.
- Mapping: MEMORY.md/USER.md -> memory/user entries; SOUL.md (+IDENTITY.md, AGENTS.md if room) -> config persona (4000 chars, truncated with a note); the IDENTITY.md `Name:` becomes a `Your name is X.` line (the system prompt's first line uses it); each SKILL.md folder -> Garnet skill, provenance `user`, name normalized to `NAME_RE`; jobs -> Garnet jobs, always `enabled: false`; allowlists (`*_ALLOWED_USERS`, Hermes approved pairings, OpenClaw `allowFrom` incl. access groups and `commands.ownerAllowFrom`, SQLite `channel_pairing_allow_entries`) -> paired identities for telegram/discord/signal with IDs Garnet can match; everything else (daily notes, persona sources, HEARTBEAT/TOOLS/BOOTSTRAP, skill supporting files, Hermes `cron/jobs.json`, full originals of anything truncated) is copied to `<workspace>/imported/<source>/<same relative path>`.
- Jobs (`jobs.ts`): cron -> cron (a 6-field form only when seconds are `0`; croner puts seconds first, croniter last), fixed interval -> heartbeat (5 min to 7 days, else skipped), Hermes `timezone` / OpenClaw `tz` kept when valid. Skipped with a reason: one-shot (`once`/`at`), script-only (`no_agent`, command/script payloads), stream/on-exit schedules, unparseable cron. Notify only to telegram/discord/signal with a known chat ID (Hermes `origin`, `platform:chat`, bare platform via `<PLATFORM>_HOME_CHANNEL`; OpenClaw `delivery.announce` `to`, heartbeat owner from `ownerAllowFrom`); `notifyWhen: always` except heartbeats. Per-job models, condition scripts and pre-run scripts are reported, not mapped.
- OpenClaw state DB (`openclaw-state.ts`) is opened `readOnly` with `node:sqlite`; the columns used are checked against `src/state/openclaw-state-schema.sql` (2026.9.8) first. An unknown layout is reported and nothing is read from that table.
- Skills (`skillreq.ts`): `{baseDir}` (and Hermes `SKILL_DIR`/`${HERMES_SKILL_DIR}`) are rewritten to the archived folder when supporting files were archived. Frontmatter `metadata` is kept as one-line JSON, plus a `requires` line (`bins`/`anyBins`, `env`, `tools`, `os`). The plan flags binaries not on PATH, secrets not set (names only, via `planOptions.hasSecret`), tools Garnet has not registered (`planOptions.tools`), shell use without `run_command`, and OS limits. Hermes bundled skills: skipped when the directory's md5 (Hermes' `_dir_hash`) matches the manifest, imported (and marked) when edited; v1 manifests without hashes are skipped.
- Memory caps: entries over the cap are dropped oldest-first (the most recent entries are kept, because both tools append). `--raise-caps` sets `memory.memoryChars`/`userChars` to fit (rounded up to 100, at most 20,000) through `deps.memory.setLimits`. Apply merges with existing Garnet memory: it appends entries not already present and never rewrites or removes existing lines.
- Persona: empty -> set; only the `garnet setup` block -> merged after it (the setup name wins; the imported `Your name is` line is dropped and reported); own text -> kept unless `--persona merge|replace`; an earlier import (its header is present) -> unchanged. Merges are cut to 4000 chars with a note; the originals are always archived.
- Safety rules (do not weaken): never import secrets (only env var NAMES are listed; the only `.env` values read are `<PLATFORM>_ALLOWED_USERS` and `<PLATFORM>_HOME_CHANNEL`, which hold IDs, validated as such); never follow a symlink whose real path leaves the source dir (or the custom workspace); skip files over 1 MB and binary files; imported text is data, never executed; the memory injection heuristic is applied to imported entries; never overwrite an existing skill, job, persona, or archived file; imported jobs are disabled.
- Idempotent: a second apply adds nothing (job ids are derived from source names; an existing id is left alone).
- Plans hold content in memory; archived copies are re-read from the source at apply time under the same containment checks.
- Testing: `node --disable-warning=ExperimentalWarning --test src/migrate/*.test.ts` (offline, temp dirs; the OpenClaw state DB fixture uses the real table definitions).
- Formats confirmed from sources: `§` delimiter, Hermes skill layout, `.bundled_manifest` `name:md5` and the hash algorithm (`tools/skills_sync.py`), `cron/jobs.json` fields (`cron/jobs.py`), `deliver` targets (`cron/scheduler_delivery.py`), pairing store files (`gateway/pairing.py`); OpenClaw workspace files, `openclaw.json` keys (`docs/concepts/agent-workspace.md`, `docs/channels/pairing.md`, `docs/gateway/heartbeat.md`), state DB tables and the `job_json` shape (`src/state/openclaw-state-schema.sql`, `packages/gateway-protocol/src/schema/cron.ts`, 2026.9.8).
