# gateway

The single source of truth for who may talk to Ruby, which conversation a message belongs to, and whether a reply was delivered.

- Public API: `Gateway` (start, stop, receive, chat, deliver, health, approvePairing), `approvePairing(store, code)` for other processes, `ApiKeys`/`RateLimiter`, `ApiServer`.
- Inbound: channel → `receive` persists to the inbox (deduped on channel/account/chat/external ID) → `dispatch`: group chats ignored; unknown senders get one pairing code per code lifetime; `/start`, `/new`, `/stop`; otherwise queued on the conversation's lane.
- Conversations: `routes` in config link chats into a shared conversation; otherwise each chat is its own. `/new` rebinds the conversation to a fresh session.
- Approvals: `persistentApprover` persists an `ask` operation with a short code and pauses the task. `/approve <code>` or `/deny <code>` from any paired chat resumes the conversation that asked; an approval is a single-use grant for that exact tool and input (hashed), so changed arguments must be approved again. Grants expire.
- Outbound: every reply goes through the outbox. Delivery retries with backoff or `retryAfterMs`, then fails. A message caught mid-send by a restart is marked `uncertain` unless the channel dedupes sends; it is never blindly resent. The same holds for a `send` that returns `{ status: 'uncertain' }`, throws, or does not settle within `sendTimeoutMs`.
- Recovery: tasks left `running` are failed and the sender is told, rather than replaying work that may have had effects. On start, inbound messages are persisted but not dispatched until every channel has started; then the pending backlog is dispatched in arrival order, so a new message cannot overtake an older one.
- Cancellation: every running task (channel or `chat()`) is registered per conversation, so `/stop` and `stop()` can cancel it.
- HTTP API: off by default; `listen` refuses a non-loopback host without an active key. Every route but `/health` needs `Authorization: Bearer ruby_<id>_<secret>`. Scopes: `chat`, `read`, `admin` (admin implies all). Keys are stored as salted HMAC-SHA256 hashes and compared in constant time. Each authenticated request is rate-limited per key and written to `api_audit`; failed authentications are audited at a limited rate (per IP and overall), keyless traffic (health, static files, demo, unknown paths) is not, and rows older than 90 days or beyond 100k are pruned hourly. Request bodies are capped (1 MB) and must arrive within 30 s (408 and connection close otherwise). With `trustProxy`, the client IP is the rightmost `X-Forwarded-For` entry. A `RubyError('conflict')` maps to 409.
- `/v1/chat/completions` is OpenAI-compatible, but Ruby keeps state server-side: only the newest user message is used, in the conversation named by `X-Ruby-Conversation` (default `default`) for that key.
- Must not: call models or tools directly (only through `Agent`), or log secrets.
